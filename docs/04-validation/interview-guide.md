# Interview guide

## Preparation

Allow 25–30 minutes. Explain that this is a student/product research project, not a sales call. Request permission for notes and keep responses anonymous. Use fictional vehicles during the demo.

## 1. Current work — 10 minutes

1. Describe the last EV that needed extra attention before departure.
2. How did you learn it needed attention? Who acted next?
3. Where are SOC, 12V observations, location and OEM instructions recorded?
4. What happens when instructions differ or conflict?
5. Which part takes the most time or produces repeated visits?
6. What information can you actually read from a stored vehicle?

Ask for a recent example or an anonymised form. Do not ask whether the proposed app sounds useful before understanding the current process.

## 2. Ownership and exceptions — 5 minutes

Who can stop charging, isolate a vehicle, release quarantine and approve departure? What happens with cosmetic damage versus a battery concern? Who resolves a conflict between storage and carrier limits? How are corrections recorded?

## 3. Prototype task — 8 minutes

Give the participant a VIN and ask them to find the vehicle, record a fictional 18% SOC with Weak 12V and explain the result. Observe navigation, errors, time and whether they understand predicted versus observed SOC.

For HSE, ask them to trace a concern through isolation and a reasoned decision. For planners, ask them to explain a destination-specific charging target. Avoid guiding clicks unless they are stuck; record any assistance.

## 4. Adoption — 5 minutes

Which existing system would supply arrivals and locations? What approval is needed to test with real data? Who owns the budget? What outcome would justify continuing after a pilot? Which feature or assumption is wrong?

## Close

Summarise what you understood, ask for corrections and request an introduction only if appropriate. Do not imply endorsement or a partnership. Send a factual thank-you manually after reviewing it; no outreach is sent by repository scripts.

Interview ID / role / date / consent / current process / recent incident / observed task time / errors / conflicting evidence / proposed change / follow-up owner. Use the [interview register](interviews/README.md).
